# LytJS 7.0.0 迁移指南（6.9.6 → 7.0.0）

> 适用对象：从 npm 安装的 **6.9.6** 升级到 **7.0.0**。
>
> 收录口径只收两类：**用户代码会崩**（导入失败、签名不兼容）与**行为静默改变**
> （不报错但结果不同）。内部重构、包结构整理、非公开签名收窄一律不收录；
> 核实后确认不成立的条目放在文末「核实后不收录」，避免误导。
>
> 每条都附删除提交或当前 `file:line`。不替代 CHANGELOG。

## 破坏性变更清单

### 1. `@lytjs/reactivity` 四个子路径被删除

升级后第一分钟：Node ESM 直接报
`ERR_PACKAGE_PATH_NOT_EXPORTED: Package subpath './scope' is not defined by "exports"`；
Vite/Rollup 报 `Failed to resolve import "@lytjs/reactivity/scope"`。

| 旧写法                                                                                   | 新写法                                                                              | 能否自动迁移 |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------ |
| `from '@lytjs/reactivity/scope'`（`effectScope` / `getCurrentScope` / `onScopeDispose`） | `import { effectScope, getCurrentScope, onScopeDispose } from '@lytjs/reactivity';` | ✅ codemod   |
| `from '@lytjs/reactivity/async'`（`asyncComputed` / `useAsyncState`）                    | `import { asyncComputed, useAsyncState } from '@lytjs/reactivity';`                 | ✅ codemod   |
| `from '@lytjs/reactivity/signal'`（signal API）                                          | `from '@lytjs/reactivity'`（主入口本来就有）                                        | ✅ codemod   |
| `from '@lytjs/reactivity/signal-component'`（`extractSignals` 等）                       | 无替代，能力已删除                                                                  | ❌ 人工      |

证据：`packages/reactivity/package.json:9`（exports 仅剩 `"."`），删除提交 `503dc32d`。

### 2. compiler 优化发射器改为 `signal-optimized` 子入口 + 显式注册

升级后第一分钟会命中两种报错之一：

- 仍在主入口导入发射器：`SyntaxError: The requested module '@lytjs/compiler' does not provide an export named 'generateSignalOptimized'`；
- `compile(..., { rendererMode: 'signal', optimizeSignal: true })` 未注册：抛错，
  消息含 `@lytjs/compiler/signal-optimized` 与 `registerSignalOptimizedGenerator`（不会静默降级）。

| 旧写法                                         | 新写法                                                                                            | 能否自动迁移 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------ |
| `@lytjs/compiler` 的 `generateSignalOptimized` | `import { registerSignalOptimizedGenerator } from '@lytjs/compiler/signal-optimized';` 并调用一次 | ✅ codemod   |
| `optimizeSignal: true` 直接编译                | 编译前先 `registerSignalOptimizedGenerator();`                                                    | ✅ codemod   |

证据：`packages/compiler/src/index.ts:354`（未注册时抛出）、
`packages/compiler/src/signal-optimized.ts:19`（注册函数），提交 `6d2e36db`。

### 3. compiler 删除十个「从未生效」的公开选项

升级后第一分钟：TypeScript 对对象字面量报
`TS2353: Object literal may only specify known properties, and 'isNativeTag' does not exist in type 'ParserOptions'`。
**运行时不会报错**——这些字段本来就不改变任何可达行为。

| 旧写法                                                                                                                                                       | 新写法                                                                                                                 | 能否自动迁移                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `ParserOptions.isNativeTag` / `decodeEntities`                                                                                                               | 删除；自定义元素改用 `ParserOptions.isCustomElement`                                                                   | 🟡 类型检查逐条指出，手工删 |
| `TransformOptions.bindingMetadata` / `isBuiltInComponent` / `expressionPlugins` / `slotted` / `inSSR` / `ssrCssVars` / `inline` / `isTS` / `isCustomElement` | 删除；内置组件见 `src/builtin-components.ts`，`:slotted()` 见 `transforms/scoped.ts`，产物形态用 `CodegenOptions.mode` | 🟡 类型检查逐条指出，手工删 |

证据：变更文件 `.changeset/compiler-decorative-options-removed.md`，删除提交 `b778c785`。

### 4. `@lytjs/vdom/transition` 删除 `globalTransitionPrefix`

升级后第一分钟：
`SyntaxError: The requested module '@lytjs/vdom/transition' does not provide an export named 'globalTransitionPrefix'`。
即使旧代码只是**写**它，也从未真正影响另一入口的读取——属于「写了不生效」。

| 旧写法                              | 新写法                                                                                    | 能否自动迁移              |
| ----------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------- |
| 读 `globalTransitionPrefix`         | `import { getTransitionPrefix } from '@lytjs/vdom/transition';`                           | 🟡 codemod 提示，手工替换 |
| 赋值 `globalTransitionPrefix = 'x'` | `import { setTransitionPrefix } from '@lytjs/vdom/transition'; setTransitionPrefix('x');` | ❌ 写时机需人工确认       |

证据：`packages/vdom/src/transition.ts:109-118`，删除提交 `29c94c9f`。

### 5. `@lytjs/devtools` 删除 `./style.css` 子路径

升级后第一分钟：
`ERR_PACKAGE_PATH_NOT_EXPORTED: Package subpath './style.css' is not defined by "exports"`。

| 旧写法                                | 新写法                                 | 能否自动迁移 |
| ------------------------------------- | -------------------------------------- | ------------ |
| `import '@lytjs/devtools/style.css';` | 删除该导入；7.0.0 不再随包提供样式文件 | ✅ codemod   |

证据：`packages/ecosystem/packages/devtools/package.json:9`（exports 已无 `style.css`），
删除提交 `7803310a`。**changeset 未覆盖**。

### 6. `@lytjs/shared-types` 删除 `EventEmitter` / `createEventEmitter`

升级后第一分钟：
`SyntaxError: The requested module '@lytjs/shared-types' does not provide an export named 'EventEmitter'`。

| 旧写法                                  | 新写法                                                 | 能否自动迁移 |
| --------------------------------------- | ------------------------------------------------------ | ------------ |
| `@lytjs/shared-types` 的 `EventEmitter` | `import { EventEmitter } from '@lytjs/common-events';` | ✅ codemod   |
| `createEventEmitter(...)`               | `new EventEmitter()`                                   | ❌ 人工      |

证据：`packages/shared-types/src/index.ts`（已无该导出），新实现见
`packages/common/packages/events/src/index.ts:321`，删除提交 `3fe73966`。**changeset 未覆盖**。

### 7. `@lytjs/bundler` 删除 `createWebpackPlugin`

升级后第一分钟：
`SyntaxError: The requested module '@lytjs/bundler' does not provide an export named 'createWebpackPlugin'`。
该函数此前只在 `beforeCompile` 打印一次「尚未实现」，从未产出插件。

| 旧写法                                    | 新写法                                                 | 能否自动迁移              |
| ----------------------------------------- | ------------------------------------------------------ | ------------------------- |
| `@lytjs/bundler` 的 `createWebpackPlugin` | 删除调用；需要 Webpack/Rspack 时自行按 loader 写法接入 | 🟡 codemod 提示，手工删除 |

证据：`packages/ecosystem/packages/bundler/src/index.ts:13`，删除提交 `3fe73966`。**changeset 未覆盖**。

### 8. `combineMiddlewares()` 返回值语义改变（静默）

升级后第一分钟：**没有报错**。此前它恒返回 `undefined`，现在会把中间件/下游的
`Response` 透传给调用方。依赖「返回值恒为 void」的代码会拿到一个 `Response`。

| 旧写法                                                  | 新写法                                                                                   | 能否自动迁移      |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------- |
| `const r = combineMiddlewares(...); // r === undefined` | `const r = combineMiddlewares(...); if (r instanceof Response) { /* 处理或显式忽略 */ }` | ❌ 人工审计调用点 |

证据：变更文件 `.changeset/middleware-response-passthrough.md`，
`packages/ecosystem/packages/web-framework/packages/middleware/src/middleware.ts:17`。

## 自动迁移

可机械迁移的条目为 4 条（reactivity 子路径、compiler 发射器、devtools CSS、EventEmitter 换包），
因此提供 codemod：

```bash
# 预览（默认，不落盘）
node scripts/codemod-v7.mjs src --dry-run

# 落盘
node scripts/codemod-v7.mjs src --write
```

脚本只改 import/副作用导入，并对无替代的条目打印 `[todo]`（`signal-component`、
`globalTransitionPrefix`、`createEventEmitter`、`createWebpackPlugin`、`combineMiddlewares`）。
它不会替你改语义，也不猜调用时机。

## 核实后不收录

- **`@lytjs/ui` 三条 CSS 资产子路径**（`index.css` / `style.css` / `styles`）：6.9.6 的
  exports 里已经存在，本次没有增删，不构成 6.9.6 → 7.0.0 破坏。它们仍无 `.d.ts`，
  Node 不能直接执行 CSS，需 bundler loader——这是资产类的既有约束，不是升级事故。
- **`@lytjs/core/runtime` 不含编译器**：6.9.6 的 `@lytjs/core` 只有 `"."` 一个导出，
  `./runtime` 是 7.0.0 新增入口，6.9.6 用户不可能已经在用，故不构成升级破坏。
- **`PUBLIC_PROPERTIES_MAP`**：`@lytjs/component` 根导出被删，但仓内文档零引用，
  属内部属性映射（非公开签名），按口径不收录。
- **`WarningLevel`**：仍从 `packages/compiler/src/index.ts:86` 导出，未删除。
- **16 个 `@lytjs/common-*` deprecated**：7.x 仍照常发布，目标 8.0.0 删除，不是本次破坏。

## 升级检查清单

1. 全局搜索旧子路径与删除名：`reactivity/(scope|async|signal|signal-component)`、`devtools/style.css`、`globalTransitionPrefix`、`createWebpackPlugin`、`createEventEmitter`。
2. 跑 `node scripts/codemod-v7.mjs src --dry-run`，确认 diff 后再 `--write`。
3. 跑 `pnpm type-check`，按 `TS2353` 删除十个 compiler 装饰性选项。
4. 启动应用，确认控制台没有 `optimizeSignal` 未注册错误（需要就先调用 `registerSignalOptimizedGenerator()`）。
5. 审计 `combineMiddlewares()` 的每个调用点，显式处理可能返回的 `Response`。
