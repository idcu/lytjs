## [未发布] - 2026-11-04（第二轮：收敛语义）

### 🐞 修复（水合的第二批 5 个缺陷 —— 上一轮「删多余节点」带出来的连锁问题）

上一轮给水合补了「收敛到客户端 vnode」，但收敛的**判定方式**本身是错的，
于是「删得太多」「删得不够」「顺序不对」三种病同时存在。

- **认领是「全局搜索」而不是「游标」**（P1）：`claimExisting` 会在容器里找第一个
  「未被占用且类型匹配」的节点。上一轮补了「新建节点插到正确位置」之后，
  「水合期间只有认领、不插入」这个前提不再成立：

  ```
  SSR:    <div><p>P</p><span>S</span></div>
  客户端: <div><span>S</span><p>P</p></div>
  ```

  `<span>` 的 vnode 跨过游标处的 `<p>` 去认领后面的 `<span>`，两个都「命中」，
  DOM 顺序却仍是 `p, span` ⇒ 与客户端直接渲染的结构不一致（下一次 patch 错位）。
  现在改为**游标语义**：只看当前位置，不匹配就返回 null、由调用方在游标**之前**新建。
  缩进用的空白文本与占位注释可以被跳过（否则复用会全丢）。

- **根节点里的资源节点被删掉**（P0）：`<script type="application/json">`（SSG 把
  序列化状态塞在根里）、`<style>`、`<noscript>`、`<link>`、`<meta>` 都被当成
  「服务端多余节点」删了 —— **丢数据、丢样式**，而且没有任何报错。
  新增白名单：这些节点的副作用在 DOM 之外，不属于 vnode，**永不删除**。

- **表单状态被无条件覆盖**（P1）：水合按 vnode 写 `value` / `checked` / `selected`，
  把**用户在 JS 到达之前输入的内容抹掉**。实测 `<input value="server">`，水合前
  `input.value = 'typed by user'` ⇒ 水合后变回 `"server"`。慢网络下这是真实场景
  （SSR 的 HTML 本来就能打字）。现在：DOM 的实时值与**它自己的初始值**
  （`defaultValue` / `defaultChecked` / `defaultSelected`）不一致 ⇒ 视为用户改过 ⇒ 保留；
  一致 ⇒ 照常收敛到客户端（两端数据不同时仍以客户端为准）。

- **多根（Fragment）根节点不做容器级收敛**（P1）：元素级收敛覆盖不到「根就是
  Fragment」的情况。实测 SSR 输出 3 个根、客户端只渲染 2 个 ⇒ 第 3 个根
  **一直留在页面上**（还带着服务端的数据）。现在 `hydrate()` 在根是 Fragment 时
  清理容器里的服务端残留（资源节点除外）。单根时不动容器里的其它内容。

- **片段锚点位置错、还会被删**（P1）：两个锚点都 `insert(..., anchor)`，水合时
  `anchor` 是 `null` ⇒ 被追加到容器末尾，`vnode.el`（起始锚点）指向片段**末尾**，
  卸载时一个子节点都摘不到；上一轮加的「删未认领节点」还会把锚点本身删掉
  （删掉后片段的更新/卸载失去定位基准）。现在：起始锚点插到第一个既有子节点之前、
  结束锚点收到「最后一个已认领子节点」之后，并登记为已认领。
  新建子节点在「没有未认领节点」时回落到调用方给的 `anchor`（片段的结束锚点），
  不再追加到片段外面。

### 🩹 契约

- `RendererOptions` / `RendererHost` 新增可选 `getFormState?(el, key)`：返回
  `{ live, initial }`，用于判断「用户是否在 JS 到达之前改过这个输入」。

### 🐞 修复（水合：`hydrate()` 之后的 DOM 与「客户端直接渲染」不一致）

水合是「服务端先送 HTML、客户端再接管」的那一步。以下 5 个缺陷**全都不报错**，
但会让 `hydrate(ssrHtml)` 的结果与 `mount()` 的结果不一样 —— 而 vnode 与真实 DOM
结构一旦对不上，**下一次更新**就会错位。

- **客户端新增的节点被追加到末尾**：水合时 `anchor` 是 `null` ⇒ 新建节点直接 append。
  实测 `SSR=<div><i>I</i></div>` + 客户端 `<div><span>N</span><i>I</i></div>`
  ⇒ 水合后 `<div><i>I</i><span>N</span></div>`。现在插在「**下一个尚未被认领的节点**」之前。
- **服务端独有的子节点不被清理**：`claimExisting` 只认领、不删除 ⇒
  `SSR` 里多出来的 `<span class="only-server">S</span>` 会一直留在页面上（脏内容）。
  现在认领元素的 children 挂载完后，删除「本次水合中从未被认领」的子节点。
- **服务端独有的属性不被清理**：应用 props 走的是 `patchProp(el, key, null, v)` ——
  只能加不能减 ⇒ SSR 的 `id` / `title` / `data-*` 在水合后仍然存在。
  现在按 `getAttributeNames` 做一次差集清理（**保留** `value` / `checked` / `selected`，
  它们是表单状态，删属性会把用户输入重置）。
- **缩进/换行的 SSR HTML 留下空白文本节点**：既不认领也不清理 ⇒
  `<div>` 的 `childNodes` 从 2 涨到 5；更糟的是**第一个文本 vnode 会认领缩进用的空白节点**
  （`'\n  '` 被改写成正文）。现在文本/注释节点新建时同样用「下一个未认领节点」作锚点，
  空白节点随后被统一清理。
- **以上全部静默**：现在 dev 下会对 mismatch 告警
  （`Hydration mismatch: <tag> not found in server HTML.` /
  `Hydration mismatch: removed N extra node(s) in <tag>.`）。
  ⚠️ 告警**不能**包在 `if (__DEV__)` 里 —— 本包的构建把 `__DEV__` 烘成 `false`，
  包起来等于把告警删掉（`warn()` 自己已有运行时判定）。

### 🩹 契约

- `RendererOptions` / `RendererHost` 新增可选 `getAttributeNames?(el)`（属性清理需要）。

## [未发布] - 2026-11-04

### 🐞 修复（P0：`ref` 在 patch 路径上永不触发）

- **`patchElement` 从不设置 `ref`**：`ref` 只在 `mountElement` 里处理，而「元素已存在、
  只是 vnode 变了」走的是 patch。最常见的两条路径都中招：
  · 组件根元素在「关闭态」是占位 `<div style="display:none">`、打开后仍是 `<div>` ⇒
    同 tag ⇒ patch ⇒ **打开后的元素永远拿不到 ref**；
  · 给已存在的元素**后来才加** ref（`v-if` 切换、条件 ref）。
- 实测后果：`@lytjs/ui` 的 `Dialog` 把焦点陷阱容器挂在根元素 ref 上 ⇒ `dialogRef()` 恒为
  `null` ⇒ **整套焦点管理（初始焦点 / 焦点陷阱 / 关闭恢复）是死代码**，而且没有任何报错。
- 现在 `patchElement` 在 `n1.ref !== n2.ref` 时先给旧 ref 传 `null`、再给新 ref 传元素。
