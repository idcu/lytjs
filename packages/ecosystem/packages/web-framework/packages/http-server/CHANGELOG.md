# @lytjs/http-server 更新日志

## [未发布] - 2026-11-03

### 🐞 协议层修复（8 个，均为「单测全绿仍存在」的静默缺陷）

- **多条 `Set-Cookie` 只剩最后一条**：数组响应头此前逐项 `res.setHeader`，后一次覆盖前一次 ⇒
  同时种 `access` / `refresh` 两个 cookie 时只到客户端一个。现在整个数组交给 `setHeader`。
- **`Content-Type` 被覆盖成 `text/plain`**：判断「用户是否设过」用的是精确小写键，处理器写
  `'Content-Type'` 时判定为未设 ⇒ 一个 JSON 字符串响应到浏览器成了纯文本。改为大小写无关判定。
- **`HEAD` 打不到 `GET` 路由**：只注册 GET 的资源收到 HEAD 一律 404（健康检查 / CDN 回源 / 监控探测全挂）。
  现在 HEAD 回落 GET（显式注册的 HEAD 优先），并保证不发体、`content-length` 与 GET 一致。
- **路径参数不解码**：`params.id` 是 `%E4%B8%AD%E6%96%87` 而不是 `中文`；`%2F` 也无法表示段内斜杠。
- **通配符路由被参数路由抢走**：优先级此前是 `score += 3/2/0` 的**总和**，`/a/b/*`(6) 输给
  `/a/:x/:y`(7) ⇒ 通配符路由注册了却永不命中。改为逐段字典序比较（静态 > 参数 > 可选 > 通配）。
- **413 / 400 没有 CORS 头**：请求体解析错误直接抛，跳过整条中间件链。现在先记录错误、照常跑完中间件。
- **错误响应丢掉中间件已写的头**：401 / 500 上既没有 CORS 也没有 `x-request-id`。现在合并 ctx 上的头。
- **方法不匹配返回 404**：路径存在但方法不对时改为 `405` + `Allow`（GET 隐含 HEAD）。

### ✨ 行为

- `content-length` 按 UTF-8 字节数显式设置；`204` / `304` 不再带体、不带 `content-length`。
- `body` 为 `0` / `false` 时仍会发送（此前按 falsy 判断会丢）。
- `@lytjs/common-query`：query 里的 `+` 按 form 编码解为空格，`%2B` 才是加号。
