**数据日期**：2026-10-11　**环境**：Node 22.22.2 + jsdom + Vitest 3.2.4（tinybench）

> ⚠️ **口径声明**：此前本报告的历史数字（README 自承「口径问题，当前没有可信数字」）已被**实测值替换**。
> 下表 `hz` = 每秒迭代次数（每次迭代执行该 bench 函数体，含其内部循环）；`mean_ms` = 单次迭代平均毫秒。
> 复现：`cd benchmarks && npx vitest bench --run`（挂载型重负载场景见文末说明）。

## 未在 jsdom 中测得（须真浏览器）

- **`fair-three-modes.bench.ts` / `memory.bench.ts`**：DOM 挂载型重负载，jsdom 下 OOM / 被系统 kill。
- **官方 js-framework-benchmark 的 1000 / 10000 行 与 全部 5 个官方操作**：官方本就在**真浏览器**测真实 DOM。
  本仓浏览器接入件见 `benchmarks/js-framework-benchmark/frameworks/`（`lytjs` / `lytjs-npm-vdom` / `lytjs-npm-vapor`）。
  jsdom 单测**不伪造**这些数字。

## 本轮修复的基准缺陷（2026-10-11）

- `js-framework-benchmark.bench.ts`：`beforeEach` 在 `bench()` 中不执行 ⇒ `container` 恒 undefined ⇒ 整套件产不出数字；已改就地建容器 + `app.unmount()` 回收 + 收敛到 jsdom 可承载子集。
- `render.bench.ts`：`import { h } from '@lytjs/vdom'` —— vdom **不导出 `h`**（`h` 在 `@lytjs/core`）⇒ 全部 bench 抛错产出 NaN；已修正导入。
