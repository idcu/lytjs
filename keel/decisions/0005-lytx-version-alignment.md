# 0005 lytx 版本对齐：对齐 npm 已发布稳定版，不追主仓分支

## 背景

生态仓 lytx（独立 repo）对 `@lytjs/*` 一律声明 `^6.6.0`，README 与文档站写"基于 LytJS v6.6.0"；
而 npm 上 `@lytjs/*` 已发布到 **6.9.6**，主仓工作分支是 `v7.0.0-dev`。
三个"版本"并存 ⇒ 口径分裂：文档说 6.6.0、实际装到 6.9.6、主仓在 7.0-dev。

实测（2026-10-09）：lytx 依赖的 **19 个 `@lytjs/*` 包全部已发布**，latest 均为 6.9.6；
`^6.6.0` 在全新安装时解析到的就是 6.9.6 —— 即"声明 6.6.0"与"实际 6.9.6"本就分离。

## 决定

**lytx 的对齐对象 = npm 已发布的最新稳定版（现 6.9.6），不是主仓分支。**

① 文档口径统一到已发布版；② 依赖声明由 `^6.6.0` 抬到 `^6.9.6`；
③ 主仓发布 v7.0.0 之后是否跟升，届时另开一篇 ADR。
本次**只定档，未实施**：声明/文档的改动须在 lytx 侧跑一次全新安装 + 构建验证后再提交。

## 被否掉的选项

| 选项 | 为什么没选 |
|---|---|
| 跟主仓 `v7.0.0-dev` | 未发布产物，别人 clone/install 取不到 —— 与"发布仓指针指向尚不存在的提交"同一种病 |
| 保持 `^6.6.0`，只改文档描述 | 留口径分裂（floor 与实际不符）；而 lytx 无外部用户，"省兼容成本"没有收益 |
| 锁死精确版本 `6.9.6` | 失去 patch 自动收益 —— 本项目 patch 极频（keel 十天内 4 个版本即例证） |

## 后果

- 好处：版本口径唯一（npm 稳定版）；不依赖主仓分支状态，clone 即可安装。
- 代价：若将来确有 6.6.0 用户需支持，要把 floor 回退（当前无此需求）；
  抬 floor 属**声明变更**，且需一次真实安装验证 —— 本次未做，勿当成已完成。
