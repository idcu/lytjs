# 0008 环境类失败不得转化为仓库改动

## 背景

坑 `sandbox-safe-delete-block` 的 `triggers` 达 3（≥ `DISTILL_AT`）⇒ keel-lint 报「待蒸馏」。
按 `GLOSSARY`，蒸馏 = **提炼进宪法** 后置 `status: distilled`。但该坑内容是**本机运维知识**
（沙箱 safe-delete 守卫拦 `build`/`coverage`、后台任务跨轮被杀、pre-commit 的裸 `pnpm`
解析到全局新版而自检失败），**写不出机械化判据** —— 而宪法第 52 行明说
「写不出检查方式的，不是硬约束，是愿望」。

⇒ 既不能原样升为硬约束，也不能伪造 `distilled`（那正是本项目最忌的「声明 ≠ 实际」，与硬约束 8 同族）。

## 决定

把该坑的**可迁移内核**提炼进宪法「人审关卡」表（**新增一行**），而非新增硬约束：

| 为"让本机跑通"而改仓库代码 / 放宽门禁（含环境类失败） | owner | decisions/ + NOW | 24h |

内核 = **环境失败 ≠ 代码缺陷**：沙箱守卫 / broker IPC / 工具链自检造成的失败，
**不得**作为改仓库代码或放宽门禁的理由；绕行只落在**本机命令**
（长任务前台跑、按 `packageManager: pnpm@11.3.0` 建 corepack shim），并登记进该坑。
随后把坑置 `status: distilled`。

## 被否掉的选项

- **新增硬约束 #10**：其内容不可机械化判死（"不得改仓库代码"没有机械判据），属"愿望"，宪法不收；
- **保持 `status: active` 让告警常驻**：把"已评估的结论"伪装成"待办"，长期变噪声；
- **只伪造 `distilled` 而不提炼**：制造"声明 ≠ 实际"。

## 代价 / 风险

「人审关卡」多一行 ⇒ 未来"为跑通而改仓库"的改动须留痕（24h 内 owner 批）。
对本项目是**净收益**：它是硬约束 2「改门禁必须注入缺陷验证」的**动机侧**补丁 ——
后者管"改了要怎么验"，本条管"什么情况下**不许**为了跑通去改"。
