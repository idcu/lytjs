# 0024 · 慢档计时断言分层：20ms 为界，低于即只报数字

## 背景

`ui/tests/performance.test.ts` 的微秒级计时断言在慢档偶发假红：
全量并发 + 覆盖率下 `signal` 从 0.07ms 放大到 9.74ms，阈值是 5ms
（`keel/pitfalls/verify/timing-flaky-parallel.md`）。放大来自调度/GC/插桩，
不是性能回退。判据口径不能靠「复跑一次就绿」维持。

## 决定

**阈值 < 20ms 的计时断言一律移出 slow 判定，只打印数字**；阈值 ≥ 20ms 的
保留为断言。20ms = 并发+覆盖率最坏观测（9.74ms）的 2 倍。不加 retry、
不改判定口径。

新增计时断言必须附实测分布（≥5 次串行 + 3 路并发）；阈值低于 20ms 时
同样只报数字，不允许以「单跑很快」为由加断言。

## 分类结果（待决 6 项 + 同原则补齐）

| 断言 | 原阈值 | 实测 max | 归类 | 处置 |
|---|---:|---:|---|---|
| props 访问 | 1ms | 0.00ms | 微秒级 | 移出，只报数字 |
| 组件初始化（Button/Input/Table/Tree） | 10ms | 0.04ms | 微秒级 | 移出，只报数字 |
| signal 创建 | 5ms | 0.28ms | 微秒级 | 移出，只报数字 |
| computed 创建 | 5ms | 0.28ms | 微秒级 | 移出，只报数字 |
| 单个组件「导入」 | 10ms | 0.02ms | 微秒级 | 移出，只报数字 |
| Table 1000 行 | 50ms | 0.03ms | 粗粒度 | 保留 50ms |
| Tree 深度 5 | 50ms | 0.00ms | 粗粒度 | 保留 50ms |
| 完整 UI 导入 | 100ms | 0.00ms | 粗粒度 | 保留 100ms |

「单个组件导入」与「Tree 深度 5」不在原待决清单里，按同一条规则归类，
不逐条凭感觉决定。

## 余量依据

- 实测分布（2026-11-08，本机）：5 次串行 + 3 路并发，上述全部样本
  ≤ 0.28ms；粗粒度三项 ≤ 0.03ms。
- 最坏观测：全量并发 + 覆盖率下 signal 9.74ms（约 139 倍放大）。
- 粗粒度阈值余量：50ms = 最坏观测 9.74ms 的 5.1 倍、实测 max 的
  ≥1666 倍；100ms = 10.3 倍。微秒级阈值（1/5/10ms）不足最坏观测的
  1.03 倍，无法留出安全余量。

## 被否掉的选项

| 选项 | 为什么没选 |
|---|---|
| 加 retry（失败重跑 N 次） | 掩盖测量不稳，判据变成「跑几次能撞上」 |
| N 次取中位数 | 仍是微秒级测量，跨 worker 的放大可能整段覆盖采样窗 |
| 全部移出判定 | 粗粒度项能区分「数量级退化」，全删等于放弃这类回归信号 |
| 维持人工复跑 | 判据依赖人的记忆，慢档无人复跑时红灯会被忽略 |

## 后果

- 好处：慢档不再因调度抖动假红；仍保留 50/100ms 量级退化信号。
- 代价：微秒级性能退化不再由门禁拦截，只能看日志；需要时由 bench 承担。
