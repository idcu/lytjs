## 症状

优化器**看起来有收益**（`stats.reduction = 2.90%`），但收益的唯一来源是**改坏用户代码**：
`x1 + 2` → `x3`、`1.5 + 2` → `1.7`、`"1+2"` → `"3"`、`x - 1 - 2` **语义翻转**（结合性）。
同时 `eval()` 被用来"求值"。

## 根因

在**已生成代码的文本**上做正则改写。正则无法区分标识符结尾的数字、数字字面量、字符串内容
与运算符结合性 ⇒ **不可能 sound**。四个"优化开关"里没有一个能成立，唯一的非 0 指标
（`reduction`）就是误伤的度量。

## 正解

- 常量折叠必须在 **AST** 上做（有类型与结合性信息），不做在文本上；
- 任何"对产物文本 replace"的优化，先给出**不误伤**的机械判据（列反例集合并逐条断言）；
- `stats` 若只有一个非 0 来源，先问：**这个来源是不是误伤**；
- 已加永久门禁 `check-src-hygiene`（`eval(` / `new Function(` / `console.log(` + 清单）。
